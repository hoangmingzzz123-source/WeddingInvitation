# P0/P1 Hardening

Verified on 2026-10-05, based on `cd18e47`.

## P0

- Vite is pinned to 6.4.3. The lockfile updates lodash, immutable, nanoid,
  picomatch, PostCSS and Rollup within their existing major versions.
- The original hero asset, `src/asset/videoCover.png`, is restored without
  changing its contents.
- Both the complete dependency audit and the production-only audit report
  zero vulnerabilities at verification time.

Vite patch reference: https://github.com/advisories/GHSA-fx2h-pf6j-xcff

## P1

- The overview and creation dialogs use the existing Radix Dialog dependency
  for focus trapping, background scroll locking and modal isolation. Closing
  returns focus to the opening control, including nested dialogs. Escape only
  dismisses the top dialog; demo shortcuts are disabled while a dialog is open.
- The mobile creation launcher remains mounted while its dialog is open.
- Mobile toolbar labels, touch targets, bottom safe area and footer clearance
  are corrected. Music controls occupy a separate position from the dock and
  back-to-top control. Dialogs can scroll in short viewports.
- All 21 catalog thumbnails are local WebP assets with 480px and 800px variants,
  responsive image selection, async decoding and fixed media dimensions.
- The real wedding keeps its wedding venue cover. It also provides the local
  thumbnail fallback. Failed responsive images clear their original `srcset`
  before selecting the fallback.
- `public/images/templates/sources.json` records the existing photo sources,
  dimensions and output sizes. New catalog entries need both image variants
  named after their template ID.

Radix reference: https://www.radix-ui.com/primitives/docs/components/dialog

Chrome/Playwright checks covered initial focus, Tab/Shift+Tab, programmatic
focus attempts, scroll locking, keyboard shortcuts, nested Escape and return
focus at 1440x900 and 320x568. The mobile menu launcher was also checked through
navigation to the creator.

The toolbar, dock, back-to-top and music control rectangles were checked on
all 20 internal demos at 320x568, 390x844, 640x360, 768x1024 and 1440x900.
Screenshots were inspected, all 21 local thumbnails decoded successfully,
and an intentionally failed thumbnail selected the local cover fallback.
The original hero rendered successfully. No browser JavaScript errors were
reported. External music embeds were blocked during these UI checks.

Browser tooling and screenshots were kept outside the application worktree;
no runtime dependencies were added for verification.
